Project128 fidelity reconstruction, revision 2

User intent: the previous approximation is not close enough. Reconstruct KQ
Sampei's actual proportions, typography, control density and positioning as
closely as available evidence allows, using historical/current screenshots and
public videos. Other MIDI players may fill undocumented interaction gaps.
Earlier continuous-build authorization remains active; no approval checkpoint.

Diagnosis: the previous surface omitted about twenty documented controls and
replaced them with extras, made tablet panels as tall as phone panels, and added
headers, branding, status and navigation blocks outside the reference layout.
Passing functional tests did not demonstrate visual fidelity. This revision
must compare reference and implementation geometry, not merely count controls.

Approach: keep the tested SpessaSynth/independent-bank architecture; rebuild the
surface from measured phone and tablet templates. Implement missing controls
with real per-part MIDI/DSP behavior. Move absolute ADSR/delay/locks and new app
features behind secondary controls. Keep all128 scrollable parts per the user's
original requirement, although the original screenshots display fewer panels.

Rejected: another recolor of the sparse five-dial rack; fake inert replicas of
missing controls; an unverified full rewrite of synthesis or proprietary code.
No copyrighted Apple font file is bundled. Use the Apple system font on iOS and
a clearly documented licensed Inter fallback on Linux. Exact KQ font identity
cannot be established from raster screenshots alone.

Full panel: Part/Channel/Patch/Low/High; Volume/Express/Pan/Reverb/Chorus/
Por/P.Time/Mno; P.Bend/Rng/K.Shft/F.Tune/Mod/V.Rate/V.Depth/V.Delay;
Attack/Decay/Release/Cutoff/Q/Soft/Sost/Hold. Phone wraps into four rows;
tablet combines the same controls into two rows. M tap/hold controls mute/solo.
Channel remains an accurate fixed routing label; Omni/None routing is not faked.
Relative ADR is centered at64; absolute ADSR remains an advanced override.

Controller implementation must preserve exact bank identity, immutable preset
samples, exact note lifetimes and per-part MIDI-preset intent. Optional normalized
performance state keeps old v1 presets importable; nested fields clone and merge
independently. True sostenuto and audible vibrato need compatibility adapters for
the pinned core. Live key ranges must never suppress a matching existing NoteOff.
Native extra NavigationStack chrome is removed while Files/MIDI/share remain.

Param popover: native grouped rows, MasterVolume/Balance/KeyShift/Tune in order,
value at top right, blue sliders and minus/plus steppers, PartTuning navigation.
Other menus use the same native-looking header/table grammar; no descriptive
marketing blocks in the playing surface. Preserve working imports and extras.

Evidence rules: distinguish directly viewed screenshots, video metadata and
inference. Direct video requests returned403; no watched timestamps or complete
four-year footage coverage may be claimed without frames actually inspected.
All reference assets remain research material, separate from runtime assets.

Verification: real PCM and controller lifecycle tests; current app regressions;
responsive bounds and full-grid browser interactions; actual native-CSP playback
and font loading; measured layout report plus new phone/tablet previews and
reference comparisons; resource sync; source ZIP lossless verified under20 MB.
Native compile/sign/device validation remains unavailable in this Linux host.
