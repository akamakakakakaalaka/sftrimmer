PROJECT 128 — iOS MIDI player design proposal
Prepared 28 October 2026. Working name only; an original app, not an official KQ product.
STATUS: Design for review. No application code, signed IPA, soundbank conversion, or device validation has been completed.

PURPOSE
Build a portrait-friendly iPhone/iPad MIDI keyboard and file player using SpessaSynth, with independent bank selection, editable individual presets, useful effects, and settings that remain consistent when changing MIDI files. KQ Sampei 26 provides a functional reference. No public KQ source or .kqspreset specification was located, so the implementation must use original code and interface assets. The accompanying 250 entries are proposed capabilities, not a claim of implementation or 250 additions absent from every existing player.

APPROACHES
Recommended: a native SwiftUI iOS shell, a locally bundled custom AudioWorklet adapter around SpessaSynth core, and a separate background worker for soundbank conversion. Native code owns Files integration, CoreMIDI, audio-session lifecycle, and persistence. The synthesizer runs in the audio worklet rather than sending individual PCM buffers across a Swift/JavaScript message bridge. This respects the requested engine while permitting native iOS integration.
Alternative: a touch web interface inside the native shell. More presentation code can run in desktop browsers, but iOS integrations, audio lifecycle and device testing still require native work. It does not remove Xcode/signing requirements.
A fully native replacement engine would change the user's chosen synthesizer and is not the proposed approach.
These are recommendations, not choices already approved by the user. Initial platform target: iOS/iPadOS 18+, foreground standalone app first. AUv3 and resilient background live synthesis have separate validation gates.

FIRST DELIVERABLE AND EXPANSION
Build a working standalone source project first: soundbank import/catalog, independent per-part bank/program routing, touch keyboard, MIDI-file transport, persistent global tuning, 128-part overview, individual preset save/recall, an absolute amplitude ADSR editor, per-preset reverb/chorus/delay sends, drum-key remapping, initial scale transformations, and selectable themes. Bank-isolation and MIDI-state regression tests are release requirements. Then expand through the catalog. Core/Expansion/Research labels indicate intended sequencing, never completion status.
Before implementing all first-deliverable screens, prove SpessaSynth AudioWorklet playback from a bundled local origin on a physical iOS device. Confirm sustained audio, worklet loading, imports, memory and native MIDI timing. A buildable source archive can be delivered from Linux; compiling and signing the native app requires a supported Mac/Xcode environment.

128 PARTS AND AN ACCESSIBLE INTERFACE
128 logical parts mean eight MIDI ports with 16 channels each; this is unrelated to the 128 GM programs. Display all 128 as an overview grid with activity, mute/solo and selected patch summary. A focused panel provides readable controls; users may also choose 8/16/32-part views. On a phone, 128 full-sized mixer strips cannot all fit readably at once. Provide portrait and landscape layouts, Dynamic Type and VoiceOver labels; the 128-cell overview is optional, not the only accessible view.
Use one synthesizer with explicitly created channels, not 128 full engine instances. Expose the port/channel identity in each part and retain file multi-port routing. Port 1/channel 10 and equivalent percussion parts are explicitly identified, not inferred only from a displayed program name.

INDEPENDENT SOUNDBANKS AND PRESETS
Every imported bank receives a content fingerprint, stable bank identifier and load generation. A part selects a concrete tuple: bank identity/generation, bank MSB, bank LSB, program and percussion mode. MIDI CC0/CC32 plus program change resolve within that part's selected bank. A missing patch is reported and can use an explicitly chosen fallback policy; another same-numbered bank must never silently take over.
Use the core's concrete MIDIChannel.preset binding through the custom adapter. The global soundbank priority stack alone cannot implement independent full-bank routing. Preserve GS and XG bank conventions, including XG percussion MSB 127; don't rewrite every percussion bank to SF2 bank 128. Display zero-based MIDI values and optional one-based labels without changing the underlying numbers.
Individual app presets are separate versioned records, not aliases for a global multitimbral snapshot. They include the bank fingerprint and exact patch, envelope overrides, effect sends, tuning and optional drum mapping. A performance can reference many individual presets. Add a separate app-preset program map and a clear target selector: bank patch changes versus saved app preset changes. MIDI alone cannot name an arbitrary filename; a user-configured bank/program map resolves the program to a saved preset ID.
Use an original documented JSON format and extension initially. .kqspreset import remains conditional on genuine example files and format validation; renaming files does not make them compatible. Missing banks should be relinkable by fingerprint with user confirmation rather than by filename alone.

REQUIRED FIXES — EXCLUDED FROM THE 250-FEATURE COUNT
F01 Bank/sample isolation. Preserve preset zones, velocity layers, stereo links, loops, modulators and exclusive classes. Namespace decoded sample data by bank identity/generation and sample index; namespace cached voices by concrete preset/overlay identity and generation, not just MIDI patch/note/velocity. Do not deduplicate different audio merely because filenames or sample names match. Existing note tails retain their referenced bank generation until voices finish. Switching to SpessaSynth alone does not establish this fix.
F02 Persistent master overrides. Master Key Shift, Master Fine Tune and other explicitly locked player settings are session/project state, separate from MIDI-file state. Loading, stopping, seeking, replaying or switching songs never resets these app overrides. MIDI controller resets and GM/GS/XG resets still update song state, after which the app's locked overrides are applied with documented precedence. Global pitch changes exclude drums by default. An explicit reset action is the only automatic-free way to clear a user lock.
F03 MIDI-format parity. Formats 0 and 1 expose the same player controls. Format 2 represents independent sequences, each with its own timing; provide pattern selection rather than silently treating all tracks as one simultaneous song. Fix the upstream experimental format-2 behavior before claiming full support. Implement and validate SMPTE time division separately from PPQN. Running status, tempo maps, port changes, long SysEx and end-of-track behavior require fixtures.
F04 Correct transformed note lifetimes. Track input note identity and its transformed output notes/pitches so note-off, sustain, seek and panic release exactly the correct voices. Changing modes mid-note must never leave stuck notes or release a neighboring part's note.
F05 Preset and effect isolation. Editing one user's preset or envelope never mutates another part's shared bank data. Settings, mute/solo and effect locks must survive recall and file transitions according to scope.
F06 Reliable save/import lifecycle. Atomic saves, cancellation without destroying originals, duplicate-bank handling by identity, explicit unsupported/corrupt-file errors, interruption recovery and missing-bank reporting are reliability fixes, not feature-count padding.

ABSOLUTE ADSR AND AUDIO LAYER-STYLE SCOPE
Use an original graphical editor with numerical Attack, Decay, Sustain and Release controls, real units, audition and reset. Amplitude ADSR is the first implementation. Sustain level is distinct from the sustain pedal. Time labels reflect actual envelope timing rather than presenting a relative CC value as milliseconds. Support original-bank values, absolute override and relative offset as visibly different modes.
AudioLayer documents separate volume, filter and pitch ADSRs and instrument/layer/zone scopes. The proposed expansion adds independent pitch and filter envelopes with clear scope and inheritance. SpessaSynth's existing shared modulation envelope does not by itself prove three independently editable envelopes; independent DSP streams need an explicit extension and audio tests. No AudioLayer source/assets are being copied.
Preserve bank data and create copy-on-write overlay identities for preset/part/instrument/layer/zone edits. Keep inheritance and reset-to-parent visible. For SF2 timecents use 1200*log2(seconds) for positive time; handle zero attack explicitly. Sustain gain g maps to -200*log10(g) centibels, with explicit handling of silence. Respect SF2 sustain/decay semantics and anti-click constraints. Any extra envelope features that SF2 cannot represent stay in app preset data and must not disappear silently during export.

HARMONY AND MICROTONALITY
Offer explicit named scale/mode presets: major, natural/harmonic/melodic minor, Hijaz, Rast, Bayati, Hirajoshi, Insen and user-defined scales. There is no single Arabic or Japanese chord system. A static tuning or scale template does not claim authentic performance practice. Supply manual source key selection, optional detection with confidence and preview, and root-based degree mapping. Exclude percussion, keyswitches and designated non-tonal parts. Preserve note length and overlapping voices; provide nondestructive bypass and undo.
Rast/Bayati-style settings may require microtones; pitch-class mapping alone is insufficient. Use explicit per-note tuning where available. For MIDI output use suitable MPE/MTS or channel allocation and identify receiving-device limits. Chord-aware reharmonization and context-sensitive maqam behavior are Research, not promised automatic conversion of any arrangement. Exports must state what transformations are baked in and what tuning messages a receiver needs.

EFFECTS AND XG
Expose reverb, chorus and delay sends per preset/part, with explicit bus choice. A per-part send amount does not imply a dedicated independently parameterized reverb unit. Use a bounded set of shared buses for normal operation; more independent inserts require CPU benchmarks and limits. Parameter changes are smoothed and bypass preserves tails when requested.
Pin the current Apache-2.0 SpessaSynth code and publish the actual supported XG effect matrix. Upstream 4.4 advertises XG but documents an S-YXG50 effect subset, unsupported-type fallbacks and calibration differences. Full XG compatibility is a conformance goal tied to named target devices/effects, not a completed capability. Avoid unsupported reverb/chorus accidentally silencing a part; surface the unsupported type and follow a documented fallback policy.
Use the existing open-source XG flanger implementation where appropriate, with editable rate, depth, feedback and mix. Add a separately labeled bitcrusher based on an audited MIT-licensed Tone.js DSP component or an equivalent measured implementation; bit-depth reduction and sample-rate reduction are different controls. Test denormals, clipping, sample-rate independence, parameter smoothing and CPU. Do not pull in a full effects framework merely for one small processor. Do not silently substitute a custom effect for a Yamaha algorithm.
For per-part custom insertion, add a deliberate pre-send voice/part hook or equivalent routing in the adapter; splitting final engine audio alone cannot retroactively alter the signal already sent to XG effects. Benchmark this before promising many simultaneous insert chains.

AUTOMATIC SF2 TO SF3
Import keeps the original by default. A compression preference may queue an automatic conversion and audition the result before adopting it. Offer quality/size estimates, progress, cancel, recovery, and A/B preview against the original. SF3 uses lossy Ogg Vorbis sample encoding; ZIP/7z packaging of the resulting file is lossless but does not restore the original PCM.
Use SpessaSynth's SoundBankLoader, setSampleFormat with a complete Ogg Vorbis compression callback, then writeSF2 for the compressed soundbank. It has no built-in encoder. The upstream wasm-media-encoders path is a candidate; audit its actual packaged license, encoder/version, iOS support and size before vendoring it. Run conversion outside the audio worklet and retain loop points, sample rates, stereo pairing, layer mappings and all preset addresses. Decode and compare results. Never repeatedly recompress an already lossy SF3 or imply smaller stored bytes mean equivalent reductions in decoded RAM.

SC-88PRO BANK AND THE 20 MB LIMIT
An authentic/proper bank needs verified source/provenance, sample inventory, GS maps and drum-kit coverage. Roland specifies 1,117 tones and 42 drum sets on the hardware; a renamed 128-preset GM bank is not equivalent. Soundfont samples alone also do not reproduce every hardware filter/effect/mixing characteristic.
No ready-to-bundle, verified SC-88Pro source was found. A large public recording collection is explicitly described by its uploader as unsuitable for MIDI-player use, has no loops, and no verified redistribution license. Do not bundle it as a finished bank. The user may provide a source they are authorized to use; until then, support imports and keep the SC-88Pro slot pending. A plainly labeled GeneralUser GS or other GM/GS fallback is possible if accepted, never represented as an authentic Roland bank.
The requested size budget is fewer than 20,000,000 bytes for the compressed source/release package including the chosen bundled bank and dependencies. This is separate from installed app size, bank-import storage and decoded RAM. A signed IPA cannot be promised to have the same size as the source ZIP. Avoid debug symbols, node_modules, duplicate builds, training assets or downloaded source caches in the deliverable.
Measure Vorbis quality candidates encoded from the original, all-preset inventories, loops, attacks, cymbals, sustained exposed notes, stereo imaging and full-song renders. Choose the smallest candidate that passes technical checks and listening, then test the whole archive size and extraction hashes. If acceptable quality and complete coverage exceed the limit, report the conflict and retain quality; obtain a decision about smaller coverage, separate bank import or the budget. No claim of "excellent below 20 MB" is justified before those measurements.

IOS LIFECYCLE AND BUILD LIMITS
Bundle all runtime assets for offline operation. Use a tested trustworthy local origin for worklet modules; validate WKWebView file/custom-scheme restrictions on device, with a loopback-only content server if necessary. Do not use an unauthenticated LAN listener. Native CoreMIDI callbacks enqueue events off the high-priority callback thread into a bounded timestamped queue; WKWebView messaging is not a hard real-time transport. Benchmark MIDI latency and event bursts before claiming live-performance readiness.
Configure AVAudioSession and test audio-route changes, interruptions, screen lock and long playback. WKWebView background synthesis is a device gate, not something a background-mode declaration guarantees. If it fails, disclose that live background synthesis remains unfulfilled. Optional native playback of pre-rendered SpessaSynth PCM is a separate constrained mode, not a silent substitute for live edits or incoming MIDI.
This environment is Linux and has no Xcode/Swift toolchain. Native compilation, signing, installation, AUv3 host validation and physical-device audio testing need a supported Mac/Xcode and an Apple signing identity. Open-source editors/build scripts do not eliminate the Apple SDK and signing requirement. Apple billing errors have their own account remedy; this project will not resolve an unpaid App Store balance.

VERIFICATION AND RELEASE ACCEPTANCE
1. Every feature has an explicit Proposed/Implemented/Verified status and acceptance checks; catalog entries are not implementation evidence.
2. Bank-isolation fixtures use different waveforms with identical preset addresses, sample names and indices across two banks. Test simultaneous parts, A-B-A changes, overlapping release tails, unload/reload, per-part overlays and mixed SF2/SF3/DLS. Compare actual PCM and zone selection.
3. A MIDI matrix covers formats 0/1/2, PPQN/SMPTE, tempo changes, multiple ports, running status, pedals, resets and program changes. Assert persistent app overrides before/after transport and song changes; verify timing from rendered audio.
4. Envelope tests measure A/D/S/R response and scope inheritance, including zero settings and unchanged neighboring parts. Effect tests verify supported SysEx, wet/dry routing, delay timing and bounded output.
5. Use an authorized bank to compare SF2 and SF3 inventories, metadata and audio through the same engine; sample audible extremes and all drum kits. Listening remains necessary for a subjective "excellent" quality decision.
6. Run automated core tests, deterministic offline renders, build checks and native/device tests. Report separately which tests actually ran. Do not label an uncompiled Xcode project as a working installed app.
7. Deliver source, reproducible lockfiles, pinned dependencies, notices, bank provenance, a truthful feature matrix and measured package bytes/hash. A signed installable build is a separate Mac/signing-dependent deliverable.

DECISIONS STILL REQUIRED FROM THE USER
Approve or revise this recommended native-shell/SpessaSynth design before product implementation. Confirm a usable SC-88Pro source when available, or choose a clearly named fallback; that bank decision need not block unrelated source development. Access to a Mac/signing identity is required for a real iOS build and device verification, not to draft source files.
Routine implementation choices, internal data types, layout spacing and test-fixture construction are delegated to the builder. No need to seek repeated approval for those details.
