# Project 128 implementation plan

> For agentic workers: execute with independent task ownership and a final integration review. The user explicitly requested continued building; no further design checkpoint is requested.

Goal: Deliver an original source project with a working SpessaSynth player and native iOS shell, plus an honest 250-feature catalog.

Architecture: SwiftUI hosts a locally bundled TypeScript/Web Audio app. A custom SpessaSynth adapter owns bank identity, part routing, sequencing and persistent overrides; CoreMIDI and Files are native bridges.

Tech: TypeScript, Vite, Node tests, Playwright, SwiftUI, WebKit, CoreMIDI, SpessaSynth 4.4.2.

Spec: ../specs/2026-10-28-project128-design.txt

Global constraints: 128 logical parts (8 ports ×16); original KQ-like app, no copied proprietary code; no SC88Pro authenticity claim for a GM/GS fallback; unsigned source is distinct from IPA; archive below20,000,000bytes; catalog exactly250 with truthful status.

Review focus: banks with identical addresses and sample names; transformed note-offs/pedals; MIDI resets after file switching; format2 independent timing; failed imports and persistence/reload.

1. State/harmony/preset model. Files web/src/state.ts, harmony.ts; tests/state.test.ts,harmony.test.ts. Export createState(), restoreState(raw), saveState(state,storage?), createPreset(state,name), applyPreset(state,preset,partId), transformNote(note,root,mode,transpose). Tests first:128parts; roundtrip retains masterpitch; preset bankidentity stays; chromaticidentity;majorminor mappings;drumexclusion in engine. Expected npm test green after red evidence.
2. Audio adapter. Files web/src/engine.ts, worklet.ts, offline.ts and vendor/patches; tests/engine.test.ts. Public class PlayerEngine exposes init,loadBank,removeBank,applyState,applyPart,noteOn,noteOff,panic,loadMidi,play,pause,stop,seek,setTempo,position,convertToSF3 and event callback onPosition. Core scope includes bank/program routing, cache namespaces, volume ADSR overlays, native XG, app delay/flanger/bitcrusher, MIDI formats and transforms. Prove separate-bank PCM with synthetic fixtures before browser UI integration; never mark experimental format2 verified without tests.
3. Interface. Files web/index.html,web/src/main.ts,style.css. Import contracts/state/engine. 128part overview, focused controls, keyboard, bank/patch selectors, MIDI transport, envelopes/effects,individual presets,drumremap,themes,exportsettings. Browser checks import/play/audio, keyboard no stucknotes,part selection,UIstate reload and errors. All visible controls must work or clearly disclose unavailability.
4. Native shell. ios/Project128.xcodeproj,Swift source,Info.plist,tools/sync-ios.mjs. Bundle dist; loopback content server handles only trusted bundled routes, Files import bridge, AVAudioSession, CoreMIDI queue. Build settings target iOS18,personal signing selectable. Verify project structure here; actual xcodebuild/sign/device tests require Mac and are reported pending.
5. Starter bank and conversion. tools/prepare-bank.mjs,notices. Source GeneralUserGS from author repo; preserve license and label fallback. Vorbis conversion from original with metadata inventory comparison; keepunderbudget. SC88Pro awaits verified source. Do not bundle a proprietary or mislabeled bank.
6. Integration, review and package. npm test,npm run build,npm run test:browser; offline renders;lintproject;catalogcount/coverage; sourceZIP excludes node_modules and caches but includes offline dist/licenses. Complete archive byte count and SHA256 extraction checks. Fresh reviewer inspects audio routing, persistence, state validation, native bridge. Report exact limits and remaining planned features.

Every behavior task starts with failing assertions, implements the minimum behavior, reruns tests, and records the result. Root owns shared contracts,packageconfig,integration,distribution docs and final package; workers own only assigned files. No worker changes another worker's interface without notifying root.
