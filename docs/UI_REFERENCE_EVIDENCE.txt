Research date: 2026-10-29

Purpose and implementation boundary
This revision reconstructs the documented KQ Sampei interface from public
references. No public Sampei application source or .kqspreset format specification
was located. This is original Project128 code retaining SpessaSynth, not a Sampei
source fork. The runtime Project128 GS bank is derived from credited GeneralUser
GS/TimGM material; it is not an authentic Roland SC-88Pro bank or hardware engine.

Direct documentation and screenshot observations
The manual specifies the full panel control set, M tap/hold for mute/solo,
keyboard scroll strip, pinch zoom, Glide/Scroll/Fixed touch modes, selecting a
panel for keyboard channel, patch sorting/search/favorites and Close-on-select.
It specifies player controls, seeking without processing SysEx, and presets
saving patch names and panel parameters while excluding sound-set state.
Screens show dense flat panels, square value fields, arc knobs, a compact
centered toolbar, bottom keyboard controls, and grouped native-style sheets.
Phone wraps controls into four rows; tablet uses two rows. User-required 128-part
scrolling extends beyond the smaller panel count shown in the references.

Typography inference and reproducibility
Regular proportional sans text and native-looking Apple sheets support choosing
the native Apple system face first on iOS. Raster references do not establish
the original font family, exact metrics or Dynamic Type settings. Linux/browser
previews use licensed Inter under the Fidelity Sans alias; this is an explicit
fallback. No Apple font binary is bundled. See web/src/typography.css and
licenses/code/FidelitySans-OFL.txt for font source, checksum and license.
The Kira Q Tech website's Titillium CSS is not evidence of the app's font.

Other-player precedents, only for undocumented gaps
https://www.bismark.jp/bs-16i and https://www.bismark.jp/bs-16i/support give an overview;
no public official manual was located. Use developer-authored release notes:
https://apps.apple.com/us/app/bismark-bs-16i/id388149926
Version 5.1.0, 2026-06-17, describes scene export/import with bank/song paths
relative to Documents. This is a portability precedent, not Sampei behavior.
Relative-path session portability is NOT implemented here: Project128 currently
uses hash-based bank identities with a reimport manifest. No .bs16iScene or
.kqspreset compatibility follows from this precedent.
https://apps.apple.com/us/app/bismark-m16/id1293998203
The companion player's v4.5 notes (2022-02-27) fix instrument reset on rewind.
This supports a deliberate override-persistence policy where Sampei's seeking
details are incomplete; it does not establish Sampei's policy or test our engine.
Sampei already documents pinch/glide, solo-hold and patch-close behavior, so those
do not need borrowed gestures. All borrowed precedents remain explicitly separate.
