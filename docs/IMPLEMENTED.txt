PROJECT128 v0.1 — current implementation and limits

WORKING SOURCE FOUNDATION
128 logical parts across eight MIDI ports. Full measured Sampei-style panel grid: phone four-row and tablet two-row templates,128 scrollable panels, reference-sized knobs/labels, thin selected border and M tap/hold-Solo. Added branding/status/navigator UI moved off the playing surface. Geometry for phone390x844, portrait768x1024 and landscape1024x768 is recorded in output/fidelity-verification.json. Current/older official screenshots and inspected2022 review images are the visual references; video playback was blocked and is not claimed as observed.
Native iOS system font stack with a local licensed Inter fallback for Linux/browser previews. No Apple font file is included; exact original KQ font identity is not proven by screenshots.
Toolbar settings/music icons now use a fine-toothed three-spoke gear and filled beamed notes. Native iOS renders installed system glyphs; browsers use authored SVG replacements. Original Sampei SVGs were not found in published sources. Provenance and native validation limits are recorded in ICON_SOURCES.txt.
Real per-part controllers: expression, modulation,14-bit pitch bend/range, RPN fine tune, relative ADR, cutoff/resonance, vibrato rate/depth/delay, portamento/time, mono, soft/sostenuto/hold and live-keyboard Low/High. Optional v1 performance state imports legacy presets safely, deep-clones and preserves exact per-leaf mapped-preset intent. Sostenuto/vibrato/mono compatibility adapters supplement the pinned open-source core. Their curves are not certified copies of proprietary KQ behavior; percussion follows MIDI RPN fine-tuning semantics.
Per-program portamento memory is keyed by concrete soundbank fingerprint plus MSB/LSB/program/drum flag. Por and P.Time edits save enabled/time automatically for that program. Another program defaults to its own setting, and settings survive reload. Normal font program selection recalls these defaults; an explicit app-preset snapshot or later controller edit retains priority.
Searchable two-column patch sheet supports names/prog ranges/bank queries, favorites, source-order and sorted views and Close-after-selection. Parameters use native-style grouped rows/steppers with real master volume, stereo balance, key shift, fine tune, reverb/chorus return gains, and Part Tuning. Absolute ADSR, delay, flanger, bitcrusher and other extra controls remain behind Miscellaneous Parameters.
Docked piano with reference key proportions/register, modulation and pitch surfaces, velocity, part destination, ruler, two-finger zoom and Fixed/Glide/Scroll touch behavior. Hiding/resizing releases its own notes without globally silencing a MIDI file. Gesture/zoom choices are session UI state. Compact sixteen-part-per-port SMF view has two columns on larger screens, a bottom transport/repeat control, actual per-part PCM meters and actual pressed-key telemetry. Other controller fields still display saved controls rather than full live MIDI feedback.
Independent concrete SF2/SF3/DLS bank/program bindings, SHA256 bank fingerprints and isolated voice caches. Synthetic mixed-format PCM tests verify equal preset/sample names do not merge voices across banks.
Per-part bank MSB/LSB/program controls, mute/solo, volume/pan, melodic transpose, drum-key remapping, effect sends and locks.
Individual original .p128preset JSON save/import/export, nested parameter isolation and bank references. Session JSON backup/restore; corrupt imports leave current state intact. KQ .kqspreset is not supported.
Per-part app-preset MIDI bank/program maps recall independent saved bank, ADSR, effects and drum snapshots. Incoming mapping addresses stay separate from font patch addresses. Repeated recalls and same-valued explicit panel edits are covered; volume/ADSR edits preserve the other recalled fields.
Absolute amplitude ADSR controls/curve display, stored with each preset. This is not full AudioLayer parity: independent pitch/filter envelopes, layer/zone UI scopes and arbitrary curves remain planned.
Touch/computer keyboard, velocity and sustain, exact note lifetimes, panic, and multi-pointer behavior.
MIDI file playback, tempo multiplier, seek/pause/resume, independent format2 sequence selection, PPQN and SMPTE timing. Master key shift/fine tune survive file changes and MIDI resets. Seeking retriggers spanning notes rather than resuming sample phase.
Chromatic, major/minor families, Hijaz, Hirajoshi and Insen scale templates/root mapping. This is a scale mapper, not context-aware chord reharmonization. Microtonal Rast/Bayati are visibly unavailable pending proper cent tuning.
Per-part reverb/chorus/delay sends; master delay time/feedback/mix, flanger mix and bit-depth reduction. Per-preset dedicated delay units and sample-rate-reduction bitcrush are not complete. SpessaSynth XG effects/SysEx are supported to the adapter's present extent, not certified full XG-model conformance; arbitrary GS/XG part-mode SysEx still has limits.
Opt-in SF2→SF3 conversion with quality/progress and originals retained for the session; low-rate PCM stays exact rather than being nearest-neighbor upsampled. File compression uses lossy Vorbis, while ZIP packaging is lossless.
Five themes including a new-session rose default; saved palettes remain intact. Local offline runtime and accessible native range controls. Full physical-device VoiceOver/Dynamic Type audits remain pending.
Native SwiftUI source: full-bleed web instrument without a duplicate native title bar, secure loopback WebKit host, Files/share bridge, settings mirrored through native storage, AVAudioSession lifecycle hooks, eight CoreMIDI input streams and bounded overflow recovery. Actual native compilation and behavior remain unverified.
Linux-triggered Mac-runner workflow, optional signed IPA export from supplied private signing secrets, and read-only Mac toolchain preflight. This is real Mac infrastructure, not macOS emulation inside Linux.

KNOWN REMAINING LIMITS
Full documented Sampei behavior parity is unfinished. Receive-channel Omni/None reassignment, all original preferences, proprietary modifiers/streaming, full advanced effects editors and other catalog goals remain outside this build. Channel displays its real fixed port/channel route. The vibrato adapter uses documented open-source compatibility curves, not an assertion of identical KQ DSP.
No signed IPA or installed iPhone build exists yet. Native compilation, signing, WKWebView local-origin worklet support, live MIDI latency, background audio, interruptions and physical-device behavior require the Mac workflow and actual hardware tests.
Custom imported bank bytes are session-memory-only and must be reimported after reopening; fingerprints and preset settings persist. The starter reloads automatically. Persistent custom bank storage is planned.
Panel values display saved controls, not complete live MIDI feedback. MIDI can recall other snapshots. Edits affect their specified fields; Apply displayed settings explicitly restores the whole visible part. A full live effective-state display is future work.
Missing patches may fall back to a patch within the selected bank without a displayed fallback warning. They never resolve against another selected bank's sample data.
CoreMIDI timestamps are currently processed on receipt rather than calibrated to the audio clock. Eight input sources are supported, with additional sources reported rather than silently merged.
AUv3, microtonal tuning, full named-model XG conformance, piano-roll editing, stem export and many other catalog goals remain future work. The250 catalog entries are proposals with explicit partial coverage, not250 finished features.
